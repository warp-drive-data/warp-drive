WarpDrive's RFCs now live in the main repo under `rfcs/` and have their own [RFCs](/rfcs/index.md)
section on the docs site. Drafting and discussion happen there first, and a bot mirrors each RFC to
`emberjs/rfcs`. Several RFCs opened this cycle; all are still at the proposed stage:

- [Dropping V1 Addon and Classic ember-cli Macros Support in 6.0](/rfcs/0004-drop-v1-addon-and-classic-macros-support.md)
  proposes that 6.0 ships every package as a V2-only addon configured only through the bundler
  plugin, ending support for non-Embroider classic builds as an ember-cli addon.
- [Deprecating the Legacy ember-data Packages and @warp-drive/core-types](/rfcs/0005-deprecate-legacy-packages.md)
  proposes deprecating `ember-data`, every `@ember-data/*` package and `@warp-drive/core-types` in
  favor of their `@warp-drive/*` successors, with removal from publishing in 6.0.
- [Deprecating Subscription-Based Request State](/rfcs/0009-deprecate-request-state-subscriptions.md)
  proposes deprecating the imperative `RequestStateService` subscription API in favor of the
  signals-backed reactive request state, with removal targeted for 6.0.
- [A Browser Devtools Extension](/rfcs/0003-warp-drive-devtools-extension.md) for inspecting
  requests, cache and schemas in Chrome and Firefox.
- For PolarisMode: [Pointer and Reference Fields](/rfcs/0006-pointer-and-reference-fields.md)
  for relationships WarpDrive never fetches, [Virtualized Resources](/rfcs/0007-virtualized-resources.md),
  and [a `$state` field](/rfcs/0008-reactive-resource-state.md) reporting a resource's lifecycle
  state and local changes.
