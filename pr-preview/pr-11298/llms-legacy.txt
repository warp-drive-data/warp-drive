# WarpDrive Legacy Packages

> API reference for the legacy `@ember-data/*` and early `@warp-drive/*` packages, kept for apps that have not yet migrated.

Most of these packages re-export a modern WarpDrive package; the modern documentation is indexed in https://canary.warp-drive.io/pr-preview/pr-11298/llms.txt.

## @ember-data/adapter

- [@ember-data/adapter](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/adapter.md): (Legacy) REST and JSON:API implementations of the Adapter interface, re-exported from `@warp-drive/legacy/adapter`; new apps should write request handlers for the `RequestManager` instead.
- [@ember-data/adapter/error](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/adapter/error.md): Legacy alias that re-exports `AdapterError` and its subclasses (invalid, timeout, abort, 401, 403, 404, 409, 5xx) from `@warp-drive/legacy/adapter/error`.
- [@ember-data/adapter/json-api](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/adapter/json-api.md): Legacy alias that re-exports `JSONAPIAdapter` from `@warp-drive/legacy/adapter/json-api` so `@ember-data/adapter/json-api` imports keep working.
- [@ember-data/adapter/rest](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/adapter/rest.md): Legacy alias that re-exports `RESTAdapter`, `fetchOptions`, and their request types from `@warp-drive/legacy/adapter/rest` so `@ember-data/adapter/rest` imports keep working.

## @ember-data/active-record

- [@ember-data/active-record](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/active-record.md): (Legacy) ActiveRecord request builders such as `findRecord` and `query` that produce underscored, pluralized URLs; new apps should use `@warp-drive/utilities/active-record` instead.
- [@ember-data/active-record/request](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/active-record/request.md): Legacy alias that re-exports the ActiveRecord-style request builders (`findRecord`, `query`, `createRecord`, `updateRecord`, `deleteRecord`) from `@warp-drive/utilities/active-record`.

## @ember-data/legacy-compat

- [@ember-data/legacy-compat](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/legacy-compat.md): (Legacy) Shims such as `LegacyNetworkHandler`, `adapterFor` and `serializerFor` that keep Adapters and Serializers working with the `RequestManager`; now published as `@warp-drive/legacy/compat`.
- [@ember-data/legacy-compat/builders](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/legacy-compat/builders.md): Deprecated request builders (`findAll`, `findRecord`, `query`, `queryRecord`, `saveRecord`) that move store method calls onto `store.request` while keeping adapter behavior.
- [@ember-data/legacy-compat/utils](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/legacy-compat/utils.md): Deprecated helpers for normalizing and checking resource types and IDs (`formattedType`, `formattedId`, `expectId`, `isEquivType`, `isEquivId`) and configuring mismatch reporting.

## @ember-data/model

- [@ember-data/model](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/model.md): (Legacy) `Model` class and its `attr`, `belongsTo` and `hasMany` decorators, re-exported from `@warp-drive/legacy/model`; new apps should define schemas for `@warp-drive/core` instead.
- [@ember-data/model/hooks](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/model/hooks.md): Legacy alias that re-exports the `Model` lifecycle hooks `instantiateRecord`, `teardownRecord`, `modelFor`, and `buildSchema` from `@warp-drive/legacy/model`.
- [@ember-data/model/migration-support](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/model/migration-support.md): Legacy helpers (`withDefaults`, `registerDerivations`, `DelegatingSchemaService`, `WithLegacy`) for migrating from `@ember-data/model` to schema-driven records in LegacyMode.

## @ember-data/json-api

- [@ember-data/json-api](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/json-api.md): (Legacy) JSON:API document and resource cache for the `@ember-data/*` packages, re-exporting `JSONAPICache`; new apps should import it from `@warp-drive/json-api` instead.
- [@ember-data/json-api/request](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/json-api/request.md): Legacy alias re-exporting request builders from `@warp-drive/utilities/json-api` that produce fetch options with stable JSON:API URLs for `store.request`.

## @ember-data/store

- [@ember-data/store](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/store.md): (Legacy) EmberData `Store` class that coordinates the cache, the `RequestManager` and record presentation; new apps should use the `Store` from `@warp-drive/core` instead.
- [@ember-data/store/configure](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/store/configure.md): Re-exports `setupSignals`, which configures the signals implementation WarpDrive uses for reactivity.
- [@ember-data/store/types](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/store/types.md): Legacy alias that re-exports the store public types (schema service, finder options, model schema, and more) from `@warp-drive/core/types`.

## @ember-data/graph

- [@ember-data/graph](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/graph.md): (Internal) Package re-exporting the relationship graph from `@warp-drive/core` for use by the JSON:API cache; not intended for direct application use.

## @ember-data/request

- [@ember-data/request](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/request.md): (Legacy) Package that once provided the `RequestManager` and its related facilities; new apps should import them from `@warp-drive/core` instead.
- [@ember-data/request/fetch](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/request/fetch.md): Legacy entry re-exporting `Fetch`, a request handler that sends each request with `fetch` and parses the response as JSON.

## @ember-data/request-utils

- [@ember-data/request-utils](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/request-utils.md): (Legacy) URL and query-param helpers such as `buildBaseURL` and `buildQueryParams` for request builders; new apps should import them from `@warp-drive/utilities` instead.
- [LifetimesService](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/request-utils/classes/LifetimesService.md)
- [@ember-data/request-utils/handlers](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/request-utils/handlers.md): Re-exports prebuilt request handlers such as `Gate`, `AutoCompress`, and `MetaDocHandler`, plus header and URL-length helpers, from `@warp-drive/utilities/handlers`.
- [@ember-data/request-utils/string](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/request-utils/string.md): Re-exports LRU-cached string inflection and case helpers (`pluralize`, `singularize`, `camelize`, `dasherize`, and others) from `@warp-drive/utilities/string`.

## @ember-data/rest

- [@ember-data/rest](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/rest.md): (Legacy) REST request builders such as `findRecord`, `query` and `createRecord` that produce camelCase, pluralized URLs; new apps should import them from `@warp-drive/utilities/rest` instead.
- [@ember-data/rest/request](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/rest/request.md): Legacy alias re-exporting request builders from `@warp-drive/utilities/rest` that produce fetch options with * stable, camelCase pluralized REST URLs. *

## @ember-data/serializer

- [@ember-data/serializer](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/serializer.md): (Legacy) JSON, REST and JSON:API implementations of the Serializer interface, re-exported from `@warp-drive/legacy/serializer`; new apps should normalize data in request handlers instead.
- [@ember-data/serializer/json-api](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/serializer/json-api.md): Legacy alias that re-exports `JSONAPISerializer` from `@warp-drive/legacy/serializer/json-api` so `@ember-data/serializer/json-api` imports keep working.
- [@ember-data/serializer/json](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/serializer/json.md): Legacy alias that re-exports `JSONSerializer` from `@warp-drive/legacy/serializer/json` so `@ember-data/serializer/json` imports keep working.
- [@ember-data/serializer/rest](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/serializer/rest.md): Legacy alias that re-exports `RESTSerializer` and `EmbeddedRecordsMixin` from `@warp-drive/legacy/serializer/rest` so `@ember-data/serializer/rest` imports keep working.
- [@ember-data/serializer/transform](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/serializer/transform.md): Legacy alias that re-exports the base `Transform` and the boolean, string, number, and date attribute transforms from `@warp-drive/legacy/serializer/transform`.

## @ember-data/tracking

- [@ember-data/tracking](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/tracking.md): (Deprecated) Package that once wired WarpDrive into Ember's reactivity system; remove it and install `@warp-drive/ember` instead, following the migration steps on this page.
- [buildSignalConfig()](https://canary.warp-drive.io/pr-preview/pr-11298/api/@ember-data/tracking/functions/buildSignalConfig.md): Deprecated: builds signal hooks that back WarpDrive reactivity with Ember tags; `@ember-data/store` registers it automatically, and `@warp-drive/ember` replaces it.

## @warp-drive/build-config

- [@warp-drive/build-config](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config.md): (Legacy) Home of the `setConfig` build plugin that configures WarpDrive deprecations, optional features and debug logging; new apps should use `@warp-drive/core/build-config` instead.
- [macros()](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/babel-macros/functions/macros.md): Returns the Babel plugin entries that turn WarpDrive deprecation, canary-feature, debug-logging, env, and assert imports into build-time code-stripping macros.
- [@warp-drive/build-config/babel-macros](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/babel-macros.md)
- [@warp-drive/build-config/canary-features](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/canary-features.md): Build-time feature flags that gate unreleased WarpDrive features, which can be activated only in canary development builds via `setConfig` or an env var.
- [ENFORCE_STRICT_RESOURCE_FINALIZATION](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/canary-features/variables/ENFORCE_STRICT_RESOURCE_FINALIZATION.md): Canary feature flag that throws in development when `schema.fields` is first called for a resource whose traits, or its traits' traits, are missing.
- [JSON_API_CACHE_VALIDATION_ERRORS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/canary-features/variables/JSON_API_CACHE_VALIDATION_ERRORS.md): Canary feature flag that makes the JSON:API cache validate payloads given to `cache.put` against registered schemas and the JSON:API spec.
- [@warp-drive/build-config/debugging](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging.md): Flags for turning on WarpDrive debug logging per area, such as cache, requests, and notifications; use it via `@warp-drive/core/build-config/debugging`.
- [DEBUG_RELATIONSHIP_NOTIFICATIONS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/DEBUG_RELATIONSHIP_NOTIFICATIONS.md): Debug logging flag that logs why a change notification fired while processing an update to a hasMany relationship.
- [LOG_CACHE](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_CACHE.md): Debug logging flag that logs cache updates to both local and remote state; it replaces `LOG_PAYLOADS`, `LOG_OPERATIONS`, and `LOG_MUTATIONS`.
- [LOG_CACHE_POLICY](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_CACHE_POLICY.md): Debug logging flag that logs the decisions the default CachePolicy makes about whether cached requests are expired or stale.
- [LOG_GRAPH](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_GRAPH.md): Debug logging flag that logs the updates the relationship graph receives.
- [LOG_IDENTIFIERS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_IDENTIFIERS.md): Debug logging flag that logs lookups, generation, and updates of the identifiers (cache keys) WarpDrive assigns to resources.
- [LOG_INSTANCE_CACHE](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_INSTANCE_CACHE.md): Debug logging flag that logs when the store creates or removes record instances and their cache entries.
- [LOG_METRIC_COUNTS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_METRIC_COUNTS.md): Debug logging flag that logs counts of key internal operations, for performance debugging.
- [LOG_MUTATIONS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_MUTATIONS.md): Removed debug logging flag that no longer has any effect; use `LOG_CACHE` to log cache updates instead.
- [LOG_NOTIFICATIONS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_NOTIFICATIONS.md): Debug logging flag that logs the change notifications the store's NotificationManager receives and delivers to subscribers.
- [LOG_OPERATIONS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_OPERATIONS.md): Removed debug logging flag that no longer has any effect; use `LOG_CACHE` to log cache updates instead.
- [LOG_PAYLOADS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_PAYLOADS.md): Removed debug logging flag that no longer has any effect; use `LOG_CACHE` to log cache updates instead.
- [LOG_REACT_SIGNAL_INTEGRATION](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_REACT_SIGNAL_INTEGRATION.md): Debug logging flag that logs how the React integration watches signals and notifies React of updates, for debugging React reactivity issues.
- [LOG_REQUESTS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_REQUESTS.md): Debug logging flag that logs each request issued through the RequestManager.
- [LOG_REQUEST_STATUS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/debugging/variables/LOG_REQUEST_STATUS.md): Debug logging flag meant to log status updates for requests the store sends to the network (adapter); it currently has no effect.
- [@warp-drive/build-config/deprecations](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations.md): Deprecation flags for WarpDrive and how to strip the code behind resolved deprecations at build time, by `compatWith` version or by individual flag.
- [DEPRECATE_COMPUTED_CHAINS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/DEPRECATE_COMPUTED_CHAINS.md): Planned deprecation flag, with no deprecation ID yet, guarding support for observer and computed chains on WarpDrive record arrays and ManyArrays.
- [DEPRECATE_EMBER_INFLECTOR](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/DEPRECATE_EMBER_INFLECTOR.md): Deprecation flag for using ember-inflector for pluralization and singularization instead of the `@ember-data/request-utils/string` utilities.
- [DEPRECATE_LEGACY_IMPORTS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/DEPRECATE_LEGACY_IMPORTS.md): Deprecation flag for importing from the legacy `ember-data/*` paths instead of `@ember-data/*`, except `ember-data/store`.
- [DEPRECATE_MANY_ARRAY_DUPLICATES](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/DEPRECATE_MANY_ARRAY_DUPLICATES.md): Deprecation flag for adding duplicate records to a ManyArray; when `false`, adding duplicates throws an error instead of being deduped.
- [DEPRECATE_NON_STRICT_ID](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/DEPRECATE_NON_STRICT_ID.md): Deprecation flag for legacy support of numeric resource IDs that are coerced to strings; set it to `false` once resolved to strip that support.
- [DEPRECATE_NON_STRICT_TYPES](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/DEPRECATE_NON_STRICT_TYPES.md): Deprecation flag for resource `type` values that are not non-empty, singular, dasherized strings; set it to `false` once resolved to strip that support.
- [DEPRECATE_NON_UNIQUE_PAYLOADS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/DEPRECATE_NON_UNIQUE_PAYLOADS.md): Deprecation flag for hasMany relationship payloads containing duplicate identifiers, which were silently de-duped and will instead error.
- [DEPRECATE_RELATIONSHIP_REMOTE_UPDATE_CLEARING_LOCAL_STATE](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/DEPRECATE_RELATIONSHIP_REMOTE_UPDATE_CLEARING_LOCAL_STATE.md): Deprecation flag for remote relationship updates discarding unsaved local changes; set it to `false`, or `resetOnRemoteUpdate: false`, to keep them.
- [DEPRECATE_STORE_EXTENDS_EMBER_OBJECT](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/DEPRECATE_STORE_EXTENDS_EMBER_OBJECT.md): Deprecation flag controlling whether the Store extends `@ember/object`; set it to `false` to stop extending EmberObject.
- [DEPRECATE_TRACKING_PACKAGE](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/DEPRECATE_TRACKING_PACKAGE.md): Deprecation flag for the `@ember-data/tracking` package, which is replaced by the Ember reactivity setup in `@warp-drive/ember/install`.
- [DISABLE_7X_DEPRECATIONS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/DISABLE_7X_DEPRECATIONS.md): Opt-in flag: set it to `false` to make deprecations backported from 6.x print and become resolvable; by default they stay silent and unresolvable.
- [ENABLE_LEGACY_REQUEST_METHODS](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/ENABLE_LEGACY_REQUEST_METHODS.md): Deprecation flag for store request methods like `findRecord`, `query`, and `saveRecord` that bypass `store.request()`; `false` strips them.
- [ENABLE_LEGACY_SCHEMA_SERVICE](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/deprecations/variables/ENABLE_LEGACY_SCHEMA_SERVICE.md): Deprecation flag that keeps the legacy schema service APIs, such as `registerSchemaDefinitionService`, enabled while warning when they are used.
- [babelPlugin()](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/functions/babelPlugin.md): Creates the Babel plugins that apply a WarpDrive build config, for projects not already using `@embroider/macros`.
- [setConfig()](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/functions/setConfig.md): Applies a WarpDrive build config through `@embroider/macros`, controlling env behavior, logging, deprecated-code stripping, and canary features.
- [WarpDriveConfig](https://canary.warp-drive.io/pr-preview/pr-11298/api/@warp-drive/build-config/types/WarpDriveConfig.md): The options passed to `setConfig` or `babelPlugin` to control WarpDrive logging, deprecation code stripping, canary features, and optional features.
