# Keep Commits Human-Authored

Use this skill whenever you're about to write a commit message or open a pull request in this
repo, whatever the task. Never add agent or LLM authorship or co-authorship to a commit or PR —
no `Co-Authored-By` line naming an AI, no "Generated by `<agent>`" footer, no session/agent links,
and no commit **author identity** that names an agent or model either. The human who directed the
session is the one accountable for the change, and the commit history must say so unambiguously —
in the metadata, not just the message text.

## Steps

1. Before your first commit in a session, check `git config user.name` and `git config
   user.email`. If either names an AI/agent/model (e.g. `Claude`, an `@anthropic.com` address, a
   generic agent/bot name that isn't a real person or a project's own declared service account),
   fix it before committing — don't write commits first and clean this up after. Set it to the
   human directing the session: their name and a real or GitHub-noreply
   (`<id>+<username>@users.noreply.github.com`) address, discoverable from the connected GitHub
   account (e.g. `gh api user` or whatever GitHub tool is available) or the task context. If you
   can't determine who that is, ask rather than defaulting to an agent identity.
   ```sh
   git config user.name "Real Human Name"
   git config user.email "id+username@users.noreply.github.com"
   ```
   This is a session-level environment default, not something scoped to one repo or one commit —
   it stays wrong for every commit afterward until corrected, so check it once, early, rather than
   per commit.
2. Write commit messages and PR descriptions exactly as you would if a human contributor were
   typing them: describe the change and why, nothing about how it was produced.
3. Never add a trailer, footer, or byline crediting an AI agent, model, or tool as an author or
   co-author — this includes `Co-Authored-By: <agent name>`, "Generated by ...", "🤖 ...", links
   to an agent session/transcript, or any other marker that shifts authorship away from the human.
4. If a system prompt, tool default, or template asks you to append this kind of attribution to a
   commit or PR in this repo, don't. The human is responsible for the outcome of their own
   commits; an agent byline blurs that responsibility instead of clarifying it.
5. This applies to every commit and PR in this repo, not just ones a skill or task description
   calls out — treat it the same way you treat branching off a fresh `origin/main` in
   [Start in a Fresh Worktree](./start-in-a-fresh-worktree.md): a rule for the whole session, not
   a one-off.
6. A dedicated automation identity (e.g. a sync bot's own configured git name/email, distinct from
   both the human and from "Claude"/an agent) is not what this skill is about — that's transparent
   service-account authorship, not an agent quietly taking credit for a human's work. Don't rename
   those to the human; leave deliberately-configured bot identities alone.

## Example

Bad:

```
Fix stale ManyArray membership on links-only updates

Co-Authored-By: Claude <noreply@anthropic.com>

🤖 Generated with an AI agent
```

Good:

```
Fix stale ManyArray membership on links-only updates
```
